# 仓库布局切换

> 状态：现行规范｜适用：部署更新器与目录迁移｜核验：2026-08-28｜依据：用户确认的分阶段计划；#20 与桥接安装记录

## 顺序

1. 合并并验证可靠性修复。
2. 在旧目录布局下合并桥接更新器，完成临时仓库升级和回退演练。
3. 经单独生产授权，在 VPS 安装桥接更新器；记录安装版本、当前代码 SHA 和验证结果。
4. 只有第 3 步明确通过，才合并目录迁移 PR。
5. 再经生产授权更新，确认服务状态与数据位置；之后才清理过渡引用。

2026-08-28 经单独授权完成第 3 步，见 [桥接安装记录](bridge-installation-2026-08-28.md)。第 5 步尚未授权、未执行。
没有线上安装证据时，迁移 PR 必须保持待合并；桥接安装不等于应用升级，也不自动授权部署。

## 必须保持

运行根目录仍为 `/opt/murmur`，`.env`、`.venv`、SQLite、照片、dossier、日志和密钥不随源码搬迁。
桥接更新器在 Git 切换前同时允许旧、新服务端目录检出；切换后按实际布局选择安装目标与测试入口。
桥接引入前的旧版允许尚无统一测试 runner；此豁免仅用于识别原安装根目录和恢复旧版，更新目标必须具备并通过统一测试入口。
只重启已经启用的服务，不启用 Bot；缺少隔离环境的服务单元不覆盖现有配置。
已运行但未启用的已知服务会在更新前阻断操作，交由管理员决定其生命周期；更新器不擅自启用或遗漏它们。

失败恢复包含旧代码、旧安装目标、更新器、服务单元与 logrotate；已经重启过的服务全部恢复，不能只重启报错的那一个。
数据库备份独立保存；布局重组没有数据库格式迁移，不用代码回退自动覆盖活跃数据库。
对配置解析出的不同 SQLite 路径分别在线备份，去重后保存，新建目录权限为 0700、备份文件为 0600；不改动既有运行文件权限。
回滚本身失败时保留事务快照和锁并打印恢复路径，禁止下一次无人值守更新覆盖恢复证据。

## 演练与证据

使用临时 Git 仓库、假 venv 和假 systemctl 覆盖旧到新、新到新、检查失败、安装失败、重启失败与脏工作区拒绝。
记录非零退出码、旧 SHA 恢复、服务重启范围及假运行数据保持不变。真实 VPS 验收单独记录，不由演练代替。
