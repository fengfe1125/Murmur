# 日期聊天与每日回顾

> 状态：现状记录（iOS 客户端）＋接口约定（服务端尚未进入 main）｜适用：iOS 与共享服务端｜核验：2026-09-24｜依据：每日回顾客户端 PR 与 2026-09-21 工作区设计；未部署生产

## 用户行为

首页仍为聊天，四个 Tab 不变。日历按本机聊天记录标出日期，可跳到当天第一条消息；只有服务端回顾的日期
可直接打开回顾，并提示原始聊天不在本机。回顾按总结、一个问题、长期记忆排列。回答问题进入首页输入框，
提交时携带问题日期，按实际发送日期保存回答。

自动整理默认当地 22:30，可在「我的」关闭或修改时间。服务端第一次报告可用且账号还没有偏好时，客户端
保存这组默认值，也就是替用户开启自动整理；这是产品上有意的默认，关闭入口始终在设置里。只显示 App 内
入口和未读版本标记，不新增推送。首次启用从当天开始，不补历史；无有效交流不生成。22:30 后的新内容更新
同一份回顾，问题保持首次发布的版本。涉及“忘记”的问题会被撤回，以免继续显示已撤销的事实；剩余来源可
重新生成问题。

客户端只在前台时激活和轮询回顾日期（每 30 秒）；轮询挂在应用外壳上，切换 Tab 不会重复，进入后台即停。

## 本机存储

聊天与照片房间存档见 [数据生命周期](data-lifecycle.md)。回顾缓存按账号散列目录保存，每日一个文件，
只加载当前详情，不含原图。纠正或遗忘成功后移除旧派生缓存；退出本机身份或删除账户时清除此账号的回顾
缓存，清除失败会在注册页说明，但不会让设备继续处于登记状态。回答问题的那一行在本机记录里保留问题日期，
重启后重发仍作为同一天的回答。

## 服务端任务与时间（接口约定，尚未进入 main）

服务端开关 `MURMUR_DAILY_REVIEWS_ENABLED=1`，默认关闭。App 根据认证后的 `/v1/reviews/config` 判断
可用性；旧客户端不需要调用新接口。

新增表位于原 App 数据库中，不移动生产数据。常驻 worker 在独立线程和独立数据库连接中运行每日任务，
不占用聊天领取通道。任务持久化在每日回顾行中，按账号和日期唯一；领取使用 10 分钟租约，失败指数退避，
重启后扫描启用以来的已完成交流补齐任务。

来源仅从持久化且 `complete` 的入站 moment 及其 committed Memory 记录导入。未发草稿、失败请求、未发
相册照片不参与；AI 的回复不能当作用户表述。交流创建时记录最近活跃设备的时区，据此固定交流归属日；
照片拍摄日期单独保存。调度按最近活跃设备的当前时区计算当地生成时间，并保存生成使用的时区。改变时区
不会把已经归档的交流重复挪到另一日。

内容指纹避免无变化重复生成；更新后的来源进入下一版本。租约与账号偏好修订号共同阻止过期任务覆盖纠正、
关闭设置或账户删除。无来源时不让模型编造内容。日志仅输出任务状态、重试及异常类型。

## 记忆与删除

每条记忆标注 `user_stated`、`image_observed` 或 `uncertain`，关联来源 ID、交流日期及必要来源摘录。
人工纠正不被自动生成覆盖；模型读取纠正后的表述，用户仍能看到原始来源。相关性召回最多 8 条，日期及
来源随条目进入上下文。

遗忘添加来源排除记录，撤销依赖同一来源的记忆，并立即清空相关派生总结与问题。重新生成只用允许的来源，
不会重新导入被排除的原记录。原始聊天不删除。纠正或遗忘后，模型历史读取还会过滤对应来源；无法逐项
追踪来源的旧 AI 回复不再进入上下文。服务端新表均随账号级联删除，后台发布前复核账号状态。原始聊天
同步、原图云备份、导出及用户确认的正式日记成稿不在本次实现范围。

## 接口

全部新增数据接口沿用现有请求认证，签名只覆盖路径；SSE 事件格式不变。

| 接口 | 用途 |
|---|---|
| `GET /v1/reviews/config` | 能力开关和当前偏好 |
| `PATCH /v1/reviews/preferences` | `enabled`、`local_time` |
| `GET /v1/reviews?before=YYYY-MM-DD` | 倒序日期、状态、版本；每页最多 90 天 |
| `GET /v1/reviews/{day}` | 总结、问题、记忆及其来源摘录 |
| `POST /v1/reviews/{day}/refresh` | 请求重整，JSON `{}`；空日返回 `empty` |
| `PATCH /v1/review-memories/{id}` | `text` 纠正，1–500 字 |
| `DELETE /v1/review-memories/{id}` | 幂等遗忘，不删除原始聊天 |
| `POST /v1/moments` 的 `daily_question_day` | 可选 multipart 字段；由服务端核对本账号问题并保存上下文 |
