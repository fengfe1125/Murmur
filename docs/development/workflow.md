# 协作与文档规范

> 状态：现行规范｜适用：开发者与自动化 agent｜核验：2026-08-28｜依据：原分支命名提案 d6b6cdc 与本轮决策

## 分支

- `main` 是唯一长期主干，代表已合并代码，不自动代表线上版本。
- 任务分支：`codex/<类型>/<范围>/<目的>`。类型使用 feat、fix、ci、docs、chore；范围取 ios、android、server、deploy、repo 或产品领域。
- 例如 `codex/docs/repo/reframe-private-memories`、`codex/ci/deploy/bridge-layout-update`。
- 名称描述改变的目的，不使用随机代号。一个目标一个 PR；同一目标必需的跨端变更可在一起，不按文件数硬拆。
- 从最新主线开始。已共享分支通过合并同步，不强推重写他人历史；合并后停止复用。

## 合并与删除

PR 写明行为变化、验证结果和部署影响。使用保留提交的 merge，便于审计和判断分支是否已合并。
CI 检查绑定当前提交；旧提交绿色不能代替新提交验收。
启用统一 gate 后只将 `Repository gate` 设为必需检查，不能要求一个可能因路径过滤缺席的工作流。

合并后自动删远端分支；本地分支仅在提交已被保留且无活跃 worktree 时删除。
worktree 要同时检查未提交、未跟踪和被忽略的个人文件；干净状态不等于可以丢弃忽略文件。
stash 和独有工作单独登记保留，不在“清理”中自动应用、清空或丢弃。

## 文档效力

新建或更新有效文档时注明状态、适用范围、核验日期与依据提交/PR。
现行规范是已接受规则；现状记录是核验快照；提案未承诺实现；归档不再指导新开发。
代码与文档冲突时先核验事实并指出差异，不以旧文档覆盖当前行为。

产品能力只在产品文档维护；构建命令在各端入口维护；部署规则在运维文档维护。
文件移动同步 Markdown 链接、脚本定位、CI 和测试资源，历史行号只供追溯。
普通文件不机械加模板；边界模块说明职责与安全约束即可。

## 发布

合并、部署、真机验收分别记录。生产操作另行授权。
