# 网易云“一起听”Phase 0 收尾验证记录

> 状态：现状记录｜适用：个人隔离 PoC 可行性闸门｜核验：2026-09-01｜依据：VPS 隔离实例、两个独立网易云账号、iPhone 真机回执、本分支测试工具及 [8 月 31 日初测记录](netease-listen-together-phase0-results-2026-08-31.md)；不代表网易云已授权

## 结论

Phase 0 技术闸门通过，但七天个人观察期尚未完成。连续两小时稳定运行、50 次混合控制、认证
失效、十分钟连续失联和意外进程退出均达到预定标准。技术可行不等于可以进入 App Store、公测
或商业化；七天内出现风控、验证码、协议漂移或需要人工修协议，仍应停止房间功能。

当前验证对象是独立研究工具，不是 `ExperimentalNeteaseRoomAdapter` 的正式 transport，也没有
修改或重启正式 Murmur 服务。私有协议进入 worker 前仍需要单独实施、评审和部署授权。

| 项目 | 结果 | 证据 |
|---|---|---|
| 两小时稳定性 | 通过 | 234 次检查全部成功，0 次失败；隔离服务随后持续运行约 11 小时 |
| 第一轮 50 次控制 | 未达延迟门槛 | 50/50 最终同步，中位数 2.546 秒，0/50 在两秒内 |

| 独立快照复核 | 通过 | 优化后 50 条命令均再次读取远端快照，歌曲与播放状态全部一致 |
| 意外进程退出 | 通过 | `SIGKILL` 后新进程不恢复旧房间，启动清理后本地状态为 `idle` |

## 延迟修正

第一轮命令路径在播放控制之后串行发送了一次即时心跳，基准工具随后又读取权威播放列表快照，
导致所有命令超过两秒。即时心跳不是确认播放状态所必需；移除它、保留十秒周期心跳，并让命令
路径直接读取
[`/api/listen/together/sync/playlist/get`](https://github.com/neteasecloudmusicapienhanced/api-enhanced/blob/f5ce55bcb46e29c8e5350ca796fb1cc9d9914acd/module/listentogether_sync_playlist_get.js)
确认目标歌曲和播放状态后，达标率提高到 98%。接口只在远端状态一致时返回 `synchronized`。

报告只保存命令类型、耗时和成功/失败计数，不保存歌曲、房间、用户、邀请或账号标识。

## 故障边界

十分钟失联使用仅在隔离工具显式开启的上游故障开关，不修改 VPS 防火墙、DNS 或正式服务。
故障期间十秒心跳持续失败，阈值前房间保持；越过阈值后本地清除房间能力并报告
`room_unreachable_timeout`。恢复上游后机器人登录仍有效，失败房间没有自动复活；随后重启执行
启动清理，结束网易云侧可能残留的房间。

认证测试通过固定参考实现的
[`/api/logout`](https://github.com/neteasecloudmusicapienhanced/api-enhanced/blob/f5ce55bcb46e29c8e5350ca796fb1cc9d9914acd/module/logout.js)
让专用测试账号真实退出。隔离服务重新验证账号后返回 `expired` 并删除本地会话，未尝试绕过
验证码或恢复旧 Cookie。

意外退出使用 `SIGKILL`，因此旧进程没有机会执行优雅关闭。新进程启动时查询账号的远端房间
状态并结束残留房间，本地不恢复旧 room handle、命令队列或协议序号。
